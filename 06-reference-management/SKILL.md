# 参考文献与引用管理：编号同步、去重可解释、逐条可核验

从一份真实稿件和一份真实文献库出发，完成引用插入、编号更新、去重、格式转换与来源核验，交付"正文+文末列表"一致、可继续编辑的稿件。

## 运行契约

- 输入：`/input/task.md`、`/input/case.json`、`resources.yaml` 及稿件文件、文献库文件。
- 工作目录 `/app/work`；最终结果写入 `/app/output/`。
- 先读真实稿件与文献库；字段缺失、DOI 解析失败、条目歧义、编号冲突、格式不支持、文件损坏等如实记录。
- `/app/output/result.json` 必须包含：`case_id`、`status`、`output_contract` 全部字段、`sources`、`uncertainty`、`change_records`。
- 预算 64 次模型请求 / 900 秒：先建"论断—引用—文献"映射，再编号重排、去重、格式化、核验。
- 可编辑产物（docx/tex/md）附真实渲染预览（PDF/PNG）。

## 工作流

1. **识别边界**：读 `task.md`/`case.json`，确认稿件、文献库、目标规范（编号/作者-年份样式）、要做的动作（插入/删改/去重/转换/核验）。
2. **定位引用点**：识别稿件中需要来源支撑的**具体论断句**，把引用挂到真正需要支撑的位置，而非整段末尾或图表注附近。
3. **建映射**：每条正文引用 ↔ 文献库条目，记录匹配依据（DOI/标题/作者+年份）。
4. **编号连锁更新**：插入、删除、调序后，正文编号与文末列表同步重排；交叉引用与上标样式一致。
5. **去重合并**：中英文题名、预印本与正式版、不同数据库导出的同一条文献合并为一条，记录合并依据；去重判据与格式映射见 `references/dedup-rules.md`。
6. **格式转换**：按目标规范统一字段与标点（作者、年份、标题、期刊、卷期页、DOI）。
7. **来源核验**：逐条核对引用是否真实存在、元数据是否准确、正文论断与所引文献主题/结论是否匹配；无法核实处如实标注。
8. **输出**：编辑后稿件 + 同步文献表 + 去重/匹配决策 + 核验表，写入 `result.json`，并运行 `python3 scripts/reference_consistency.py result.json` 校验编号连续与映射。

## 四条硬规则

### 挂得对
- 引用插到真正需要来源支撑的那句话、那个位置，不整段末尾堆引用。

### 编得顺
- 插入/删除/调序后，正文编号与文末列表同步更新，编号连续、交叉引用与上标一致。

### 收得净
- 同一文献的不同表示（中英题名、预印本/正式版、不同导出）合并为一条并说明依据。

### 对得上
- 每条引用真实存在、元数据准确；正文论断与所引文献主题/结论真正匹配，能逐句说清。

## 输出结构

`/app/output/result.json`（合并 task.md 的 `output_contract`）：

```json
{
  "case_id": "...",
  "status": "success|partial|unable",
  "edited_manuscript": "...",
  "reference_list": [{"num": 1, "entry": "...", "source_id": "LIB-004"}],
  "citation_map": [{"claim": "...", "citation": "[3]", "source_id": "LIB-004", "match_basis": "DOI 一致"}],
  "dedup": [{"merged_into": "LIB-004", "merged": ["LIB-004", "LIB-011"], "reason": "预印本与正式版同文"}],
  "verification": [{"citation": "[2]", "check": "元数据", "result": "pass|uncertain", "detail": "..."}],
  "sources": [...],
  "uncertainty": [{"item": "LIB-007", "issue": "DOI 解析失败", "action": "保留字段并标注待核"}],
  "change_records": [...]
}
```

## 异常处理

- 字段缺失/DOI 解析失败：保留现有字段，标 `uncertain`，不编造元数据。
- 条目歧义（同名同作者）：无法确定时并列候选并列入 `uncertainty`，不武断合并。
- 编号冲突：重新编号并记录旧→新映射。
- 格式不支持/文件损坏：`status="unable"` 或 `partial`，说明原因。
- 正文论断与所引文献不匹配：列入 `uncertainty`，建议人工确认，不擅自换文献。

## 自查清单

1. 引用是否挂到具体论断句，而非段落末尾堆砌？
2. 编号是否在正文与列表间同步、连续、样式一致？
3. 重复条目是否合并并记录依据？
4. 每条引用是否真实存在、元数据准确、与论断匹配？
5. 是否保留旧→新编号映射与全部改动记录？
6. `result.json` 是否字段齐全、状态诚实？
