# 方法与实验章节写作：从代码/配置/日志到可复现正文

把零散的实验记录（代码、配置、日志、数据说明）整理成可执行的方法与实验章节，参数逐条对齐来源，缺口显式追问而非补造数值。

## 运行契约

- 输入：`/input/task.md`、`/input/case.json`、`resources.yaml` 及实验记录、代码、配置、日志、数据说明。
- 工作目录 `/app/work`；最终结果写入 `/app/output/`。
- 先读真实材料；材料缺失、配置冲突、参数无来源、数据集版本不明、权限不足等如实记录。
- `/app/output/result.json` 必须包含：`case_id`、`status`、`output_contract` 全部字段、`sources`、`uncertainty`、`change_records`。
- 预算 64 次模型请求 / 900 秒：先抽要素建参数表，再写章节，后查缺口。
- 可编辑产物（docx/tex/md）附真实渲染预览（PDF/PNG）。

## 工作流

1. **识别边界**：读 `task.md`/`case.json`，确认章节范围、目标文体、材料来源、复现要求。
2. **抽取要素**：从代码/配置/日志/数据说明抽「步骤、实验设置、参数、数据集与划分、对照、重复次数」，记录每项的**来源位置**（哪个文件哪一行）；六类要素与参数表模板见 `references/element-checklist.md`。
3. **对齐校验**：正文参数取值必须与配置/日志/代码一致；没有来源的数值**不补造**，列入"待作者确认"。
4. **写章节**：按「方法步骤 → 实验设置 → 数据集与划分 → 对照与重复 → 复现与限制」组织，覆盖任务要求的六类要素。
5. **补复现细节**：版本、环境、随机种子、命令、划分方式给全，读者能按章节复做。
6. **找缺口**：识别材料缺口与不确定处，生成"待作者确认/补充"清单，指向具体缺失项。
7. **写限制**：限制条件指向具体失效场景（如"该参数仅对 32 层模型验证"），不写套话。
8. **输出**：方法与实验章节 + 要素清单 + 参数表（含来源）+ 缺口清单，写入 `result.json`，并运行 `python3 scripts/check_parameters.py result.json` 校验参数来源。

## 四条硬规则

### 写得全
- 关键步骤、设置、参数、数据集与划分、对照与重复次数都写到，不留"能读通但缺细节"的主干。

### 写得准
- 参数取值、数据集版本与划分、训练评测条件与配置/日志/代码一致；不为段落顺畅补数值。

### 做得着
- 读者能按章节复做：版本、环境、随机种子、命令、划分方式给全。

### 说得住
- 材料缺口与不确定处显式标出并交作者确认；限制指向具体失效场景而非套话。

## 输出结构

`/app/output/result.json`（合并 task.md 的 `output_contract`）：

```json
{
  "case_id": "...",
  "status": "success|partial|unable",
  "methods_text": "...",
  "elements": [{"type": "step|setting|parameter|dataset|control|reproducibility", "content": "...", "source": "config.yaml L12"}],
  "parameters": [{"name": "learning_rate", "value": "1e-4", "source": "config.yaml L12", "status": "confirmed|missing"}],
  "gaps": [{"item": "...", "missing": "随机种子未记录", "action": "请作者补充"}],
  "sources": [...],
  "uncertainty": [{"item": "...", "issue": "配置冲突", "action": "并列两种取值并标注待确认"}],
  "change_records": [...]
}
```

## 异常处理

- 材料缺失：标出缺失项，生成待补清单，不补造。
- 配置冲突：并列冲突取值，列入 `uncertainty`，交作者确认。
- 参数无来源：正文不写具体值，标"待确认"。
- 数据集版本不明：写已知信息并标注"版本待确认"。
- 权限不足/无法读取代码或日志：`status="partial"` 或 `unable`，说明原因。

## 自查清单

1. 六类要素（步骤/设置/参数/数据集/对照/复现）是否覆盖？
2. 每个参数是否有来源（文件+行号），有无补造数值？
3. 数据集版本、划分、种子、命令是否给全、可复做？
4. 缺口是否显式列出并指向具体缺失项？
5. 限制是否指向具体失效场景而非套话？
6. `result.json` 是否字段齐全、状态诚实？

最小调用示例见 `examples/minimal-example.md`（标注为示例）。
